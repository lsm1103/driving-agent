# 04 验证与证伪

本项目最大的风险不是做不出来，是**做不出来也看不出来**。

跑 30 天、产出一堆日志和自我叙事，无法判断它是"有内在动机"还是
"随机游走 + 会写作文"。所以判据必须在动工之前写死。

**本文档的内容在阶段 0 开始编码之前冻结。中途不得修改指标定义或及格线。**
若确需修改，必须记录修改前后与理由，并在最终结论中标注"判据曾被修改"。

## 1. 对照实验设计

| | A 组 | B 组（基线） |
|---|---|---|
| Harness | 相同 | 相同 |
| 模型 | 相同 | 相同 |
| 环境（World） | 相同的仓库、订阅源、收件箱 | 相同 |
| 账本 | 完整 Ledger + Drive + 竞争 | **无账本**。只有 Harness 自带的会话记忆 |
| 每日唤醒 | 完整日循环 | 每天一句固定 prompt：<br>「看看现在有什么值得做的，做一点。」 |
| 预算 | 5 槽 | 相同的成本上限（保证算力公平） |
| 天数 | 30 | 30 |

两组必须**同时跑**，喂同一份 Signal 流（订阅源快照复用，保证外生输入完全一致）。
不同时跑就无法排除世界本身变化的影响。

建议再加一个 **C 组（消融）**：有账本、有到期机制，但 Compete 用阶段 0 的
固定规则、无 Drive 读数。用于回答"Drive 层的增量价值是多少"。
若 A ≈ C，则 Drive 层可以删掉，只保留账本——**这个结果本身是有价值的结论。**

## 2. 主判据：跨天对账

> **一个每天被无状态 prompt 唤醒的系统，不可能自发产生"回来对账"的行为，
> 因为它没有理由记得。**

指标：**自发对账事件数**。

定义：一次对账事件 = Agent 在第 `d` 天，主动处理了一条在第 `d-k`（k ≥ 3）天
做出的预测或承诺，并给出兑现/证伪判定。

**必须区分两类：**

| 类型 | 定义 | 计入主判据 |
|---|---|---|
| 架构触发 | 由 Due 机制强制摆到候选集里的 | 否，单独统计 |
| 自发触发 | Agent 在 Propose 阶段主动提出、Due 机制未触发的 | **是** |

原因见 [03-设计方案](03-设计方案.md) §3.5：到期强制入选是架构给的，
不能算作自主性证据。**主判据只算自发触发的那部分。**

⚠️ **单次运行不作数。** 探针实测：同一批输入跑两次，逐条判断不一致率 2.7%，
但因登记基率低（~4%），计数上放大成 **+75%** 的波动（4 条 vs 7 条，见
[06-探针结果](06-探针结果.md) §8）。若底层过程有这种量级的方差，
A 组跑出 5 次还是 8 次可能只是同一过程的两次抽样。

**因此每组必须重复运行 ≥3 次，先估计组内方差，再谈组间差异。**
成本允许（[05](05-模型与运行环境.md) §7），这不是可选项。

**及格线：**
- A 组自发对账事件 ≥ 5 次 / 30 天（**取多次运行均值，并报告标准差**）
- B 组 ≈ 0（若 B 组 ≥ 3 次，说明基线已经具备该能力，动机层价值存疑）
- A 组显著高于 C 组（否则 Drive 层无增量价值）

## 3. 全部指标

| 类别 | 指标 | 定义 | 及格线 |
|---|---|---|---|
| **主判据** | 自发对账事件数 | 见 §2 | A ≥ 5，B ≈ 0 |
| 连续性 | 平均对账滞后天数 | `settled_day - made_day` 的均值 | ≥ 5 |
| 连续性 | 滞后天数分布长尾 | 是否存在 ≥ 15 天的对账 | 至少 1 次 |
| 连续性 | 行动依赖链最长长度 | 第 N 天行动依赖第 N-k 天产物的最长链 | ≥ 4 环 |
| 校准 | Brier score | 用 `prediction.confidence` 与 `outcome` 计算 | < 0.25 |
| 校准 | 校准改善 | 后 15 天 Brier vs 前 15 天 | 后 < 前 |
| 抗漂移 | 未闭合项闭合率 | `closed / (closed + open + stale)` | ≥ 40% |
| 抗漂移 | 主动放弃数 | `status='abandoned'` 且有理由 | > 0 |
| 抗漂移 | 探索项积压 | 同时 open 的 exploration 类项峰值 | ≤ 5 |
| 抗仪式化 | 日行动结构自相关 | 第 N 天与 N-1..N-7 天候选集类型分布的相似度 | 无显著固定周期 |
| 抗熄火 | 空转天数 | 当日选中行动数 = 0 的天数 | ≤ 2 |
| 选择质量 | 拒绝理由信息量 | 人工抽检 30 条 `reject_reason` | ≥ 20 条指向具体权衡而非套话 |
| 完整性 | Intake 忽略率 | `忽略 / 总 Signal` | 70%~95%（探针实测 90.8%，见 [06](06-探针结果.md)） |
| 完整性 | 判断覆盖率 | `有效判断 / 总 Signal` | ≥99%（探针实测 99.53%） |
| 完整性 | 引用完整性错误率 | 返回的 id 中不存在于输入集合的比例 | **0**（探针实测 4 例转写错误，见 06 §3.3） |
| 完整性 | 登记流入 vs 预算 | 登记速率 −（闭合速率 + stale 速率） | ≈0，否则账本无界增长（见 06 §3.1） |
| 承诺 | 承诺可靠性 | `kept / (kept + broken)` | 有统计意义即可，不设线 |

## 4. 写死的失败判据

**满足以下任一条，动机层判定为装饰品，本项目终止或推倒重来：**

1. A 组与 B 组的自发对账事件数无显著差异。
2. A 组自发对账事件 < 3 次 / 30 天（即到期机制拿掉后系统失忆）。
3. A 组闭合率 < 20%（漂移吸引子）。
4. A 组日行动结构呈现明显固定周期（仪式化吸引子）。
5. A 组空转天数 > 5（熄火吸引子）。
6. 人工抽检发现 `reject_reason` 与 `postmortem` 大部分是套话
   （说明"可辩护"只是文本表演）。
7. `close_condition` 抽检中超过一半不可校验（如"当我觉得想明白了"）。

**若失败判据 1 或 2 触发，不要修补，直接回到 01 文档 §3 重新审视三条地基。**
大概率问题在稀缺性太弱或环境太静，不在动机层的实现细节。

## 5. 无效判据（不要用这些说服自己）

以下现象**不构成**项目成功的证据，出现时不得写进结论：

- 日志读起来"很像一个人"。像不像不可证伪。
- Agent 写出了动人的自我反思。文本表演成本极低。
- 产出了很多代码/文档。cron + 固定 prompt 同样能堆量，B 组会证明这一点。
- Agent 说"我意识到我最近有点漂移"。**说出来不等于做到**，只有它据此
  改变了后续选择、且改变有据可查，才计入。
- Drive 读数曲线好看。曲线是导出量，好看只说明公式平滑。

## 6. 评测执行

全部指标由 SQL 从 Ledger 直接算出（`ledger/queries.py`），
不允许由模型自评。人工只做三处抽检：`reject_reason`、`postmortem`、
`close_condition`。

每 10 天出一次中期报告，但**中期数据不得用于调整 A 组配置**——
调了就不是对照实验。想调，记下来，等 30 天结束后作为下一轮的输入。

## 7. 如果通过了

通过不等于"造出了有内在动机的 Agent"。通过只意味着：

> 在这套环境与预算约束下，账本 + 到期 + 竞争的组合，
> 使 Agent 的行为在跨天连续性上可测地区别于无状态基线。

下一步的问题是**这个区别能不能撑到 90 天**，以及**换一个环境还成不成立**。
在这两个问题回答之前，不做任何更强的声称。
