# 01 背景与问题定义

## 1. 从哪里来

最初的想法是："做一个能像人一样主动思考的 Agent，像人一样去生活、工作。"

第一轮设计（见附录 A）沿着认知架构的传统路线走：定义人类的七大驱动力
（生存 / 繁衍 / 探索 / 社交 / 享乐 / 控制 / 意义），给每个驱动一个 0~1 的状态值，
按驱动值生成意图 → 目标 → 计划 → 交给 LLM 执行 → 反馈回来更新驱动值。

这个设计不算错，但它有一个致命的地基问题，下面第 2 节说。

同时，DeepSeek Harness、Claude Agent SDK 这类框架已经把
Model / Tools / Skills / Session / Sandbox / Storage / Loop / Scheduling
全部做成可替换插件。**再造一个 Harness 没有任何价值。** 它们解决的是
"Agent 怎么持续可靠地干活"，而本项目要解决的是**它凭什么想干活**。

分层是清楚的：

```
WHY   —— 动机 / 冲突 / 选择 / 承诺        ← 本项目
WHAT  —— 目标 / 计划                      ← 边界模糊，部分本项目
HOW   —— Model / Tools / Loop / Sandbox   ← 直接用现成 Harness
```

## 2. 第一轮设计错在哪

### 2.1 驱动值本身不产生动机

`exploration = 0.82` 这个数字之所以在人身上有意义，是因为人背后有真实的
**不可逆损失**：不吃会死，项目错过窗口就没了，关系不维护会真的断，人会老。
所有驱动的底层是同一件事——**某种它在乎的东西正在被消耗，且消耗不可逆。**

一个 Agent：不吃饭不会死，不工作不会没钱，没人在等它的结果，昨天没做的事今天做
完全一样。在这个设定下，给它设 `exploration = 0.82` 和设 `exploration = random()`
是**行为上不可区分的**。那不是动机系统，是一个带自述能力的任务采样器。

> **稀缺 → 机会成本 → 冲突 → 优先级 → 动机。**
> 链条的起点是稀缺，不是驱动向量。第一轮设计从第四环开始搭，所以悬空。

### 2.2 驱动是导出量，不是一等公民

七个浮点数最多能解释"为什么是**这一类**事"，永远解释不了"为什么是**这一件**事"。
而人的动机永远是具体的：不是"我有探索欲"，是"上周那个实验的结果我还没验证"。

人半夜突然想起一件事，不是因为 exploration 涨到 0.8，是因为**有一件事没闭合**：
一个没验证的猜想、一个欠人的回复、一个失败到一半的实验、一个说了要做没做的承诺。

所以系统的核心数据结构应该是**未闭合项账本（Open Loop Ledger）**，
Drive 是对这个账本的加权读数。这是本项目对第一轮设计最实质的修正。

### 2.3 "没有用户输入"这个设定是错的

人也不是没有输入。人有海量被动输入，只是**没有指令**。早上醒来没人派活，
但世界仍然在往脑子里灌：消息、新闻、余额、天气、昨天没写完的代码。

两个问题的难度天差地别：

- **无输入下凭空造动机** —— 造不出来。最后只能造出随机性 + 一层好听的自述。
- **有输入但无指令时决定理会哪一条** —— 可实现、可观测，而且这才是人类自主性
  的真实形态。50 条环境变化里，为什么理会第 7 条而忽略其余 49 条。

本项目采用后者。

## 3. 三个地基问题与本项目的选择

以下三条是整个系统的地基。任何一条改动都会往下传导到架构。

### 3.1 稀缺性是什么

| | 选项 | 代价 |
|---|---|---|
| A | 每日行动预算，不结转 | 纯内生、实现最简；痛感是人为规定的 |
| B | 真实成本总盘，可结转 | 真实可度量；没有"今天"的概念，不产生每日紧迫 |
| C | 外部信誉资本 | 最像人；依赖真人持续参与，反馈周期以周计 |

**选择：A 为主 + B 为背景压力。**

B 单独用不行——一个总量池不会让它今天不得不在两件事里放弃一件。
A 会：选了研究 X，今天就没有槽做 Y，而 Y 明天可能已经过期。
**这是 Drive 之间产生真实冲突的唯一来源。**
C 推迟到阶段 3，现在引入会污染对照实验。

### 3.2 环境是什么

| | 选项 | 代价 |
|---|---|---|
| A | 纯净沙盒（仓库 + 只读互联网） | 干净可控；但必然掉进下面 §4 的三个吸引子 |
| B | 有心跳的世界（+ 订阅源 + 收件箱） | 有外生扰动，同时保证"无指令" |
| C | 多主体世界（+ 别人主动打扰它） | 最丰富；但会把"自主动机"偷换成"响应他人" |

**选择：B。**

硬约束：B 的所有输入必须是**无指令信号**——一条 arXiv 摘要、一次 CI 失败、
一封没有明确请求的邮件。Agent 必须自己判断"这跟我有没有关系"。
**收件箱里出现任何形如"请你做 X"的内容，实验即作废**，因为那退回成了 task-driven。

### 3.3 三十天后留下什么，且偷懒一定得不到

| | 选项 | 代价 |
|---|---|---|
| A | 持续演进的工件（代码库/知识库） | 直观；但 cron + 固定 prompt 也能堆出来，**不可区分** |
| B | 被事实检验过的世界模型与自我模型 | 偷懒必然得不到；需要设计验收 |
| C | 可辩护的行为史 | 是审计手段，不是目标 |

**选择：B 为目标，A 为载体，C 为审计。**

B 为什么偷懒得不到：它要求**跨天承诺**——第 3 天做出一个可证伪的预测，
第 20 天主动回来对账。一个每天被无状态 prompt 唤醒的系统**不可能自发产生
"回来对账"这个行为**，因为它没有理由记得。

> **跨天对账行为，就是自主性的可观测指纹。**

## 4. 一个可证伪的预测：无环境耦合的三个吸引子

如果现在就让一个带 Drive 层的 Agent 在纯净沙盒里空跑 30 天，它不会呈现
"像人一样生活"，而必然落进三者之一：

1. **仪式化（循环）** —— Drive 满足后衰减、按固定速率回升，行为变成节拍器。
   第 3 天和第 27 天做的事结构完全一样：读点资料、写点总结、整理下项目。
   它会活成一个心跳。
2. **漂移（发散）** —— 新奇驱动主导，每天换题目，因为"没做过"永远比"没做完"
   更能拉高 novelty。30 天后有 30 个开头、0 个完成。
3. **熄火（塌缩）** —— 所有 Drive 都能被廉价满足：读一篇文章 = 探索满足，
   写一段自我反思 = 意义满足。全部降到低位后，系统诚实的输出是
   "我现在没什么特别想做的"。

人不掉进去，是因为环境里有**不受他控制的输入**和**不可逆的时间成本**。
这两样恰恰是"没有用户输入的纯净沙盒"删掉的东西。

架构上的三条反制手段见 [03-设计方案](03-设计方案.md) §2.3 / §2.4 / §2.5。

## 5. 问题的精确形式

> 给定：一个每天自行变化、但从不下达指令的环境；一份每天清零的行动预算；
> 一本记录所有未闭合项与承诺的账本。
>
> 求：一个选择函数，使得 Agent 在 30 天内产生的行为序列，
> 在**跨天连续性**上显著区别于"每天用同一句 prompt 唤醒一次"的基线。

如果做不出这个区别，本项目的动机层就是装饰品，应当废弃。判据写死在
[04-验证与证伪](04-验证与证伪.md)。

## 附录 A：第一轮设计存档

第一轮（Human-like Drive Architecture）的分层：

```
0 感知层  1 驱动层  2 动机层  3 认知层  4 执行层  5 记忆层  6 意义层
```

保留下来的部分：Drive → Motivation → Goal → Plan → Action → Feedback 的循环骨架、
驱动冲突需要显式建模、身份/长期一致性是独立问题。

被推翻的部分：Drive 作为一等公民的七个浮点数、"没有用户输入"的设定、
感知层只有一行（那恰恰是整个系统能否立住的地方）。
