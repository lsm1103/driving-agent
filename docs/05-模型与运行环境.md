# 05 模型与运行环境

本文所有事实**均已对 DeepSeek API 实测验证**（验证日期：2026-08-25），
不是从文档或记忆推断。凡标 ⚠️ 的是与原设计冲突、已导致设计改动的点。

## 1. 结论速查

| 项 | 值 |
|---|---|
| 模型 | `deepseek-v4-pro` |
| Endpoint | `https://api.deepseek.com`（直连，无网关） |
| 协议 | OpenAI 兼容 `/chat/completions` |
| 凭证 | `.env` 中 `deepseek_Key`（已 gitignore） |
| 上下文窗口 | 1M token |

| 严格 JSON Schema | ⚠️ **不可用** |
| 函数调用 | ✅ 可用，但 ⚠️ 仅 `tool_choice:"auto"` |
| 推理档位 | `none / minimal / low / medium / high / xhigh / max` |
| Prompt Caching | ✅ 自动，命中价差 **30 倍** |

可用模型（实测 `GET /models`）：`deepseek-v4-pro`、`deepseek-v4-flash`、
`deepseek-v4-flash-vision-exp`。

## 2. ⚠️ 结构化输出：没有严格模式

实测 `response_format: {"type":"json_schema", ...}` 返回：

```
400 This response_format type is unavailable now
```

可用的只有 `{"type":"json_object"}`（自由 JSON，无 schema 约束）。

**对设计的影响**：03 文档 §3.2 那四条硬约束**必须全部在代码侧执行**，
一条都不能指望模型侧保证。原设计已经是代码侧校验，所以方向没错，
但现在要额外加一层**校验—重试**（见 §5）。

### 替代路径：函数调用

实测可用，且能正确遵守 enum：

```json
{"tool_calls":[{"function":{"name":"register_open_loop",
 "arguments":"{\"statement\":\"CI在macOS上连续3天失败\",
   \"close_condition\":\"CI在macOS上恢复连续通过\",\"kind\":\"maintenance\"}"}}]}
```

⚠️ **但强制调用不可用**。实测 `tool_choice:{"type":"function",...}`：

```
400 Thinking mode does not support this tool_choice
```

只能用 `tool_choice:"auto"`。关闭 thinking（`"thinking":{"type":"disabled"}`）
后强制调用可用——但审议层恰恰需要 thinking，所以这条路只对纯机械步骤有意义。

**结论**：审议层走「thinking 开 + `tool_choice:"auto"` + 强提示 + 代码校验 + 有界重试」。

## 3. ⚠️ 推理 token 计入输出计费，且吃 max_tokens

`deepseek-v4-pro` 是推理模型，返回里 `reasoning_content` 与 `content` 分离，
`usage.completion_tokens_details.reasoning_tokens` 单独报数。

两个后果：

1. **推理 token 按输出价计费**，成本估算必须把它算进去。
2. ⚠️ **推理吃 max_tokens**。实测 `max_tokens=200` 时，模型全部用在推理上，
   `content` 返回空字符串——**没有报错，静默产出空结果**。

**因此审议层每个调用的 `max_tokens` 一律给足（≥8000）。**
这是一个静默失败模式，必须在代码里显式检查 `content` 非空 + `finish_reason != "length"`。

## 4. 推理档位与 effort 分层

实测七档全部可用：`none / minimal / low / medium / high / xhigh / max`。

按 03 文档「把算力花在咽喉步骤上」的原则分配：

| 日循环步骤 | reasoning_effort | 理由 |
|---|---|---|
| Intake | `low` | 机械筛选几十条信号 |
| Propose | `high` | 生成候选，需要发散 |
| **Compete** | **`xhigh`** | **唯一真正的决策点** |
| Reckon | `high` | 写 postmortem，需要诚实归因 |

这是设计手段（算力分配随决策重要性），省钱是副作用。
三组 A/B/C 的档位配置必须完全一致。

## 5. 校验—重试层（因 §2 而新增）

每个审议层调用统一走这个包装：

```
call(step, schema, effort, max_tokens=8000)
  ├─ 发请求（thinking 开，tool_choice auto）
  ├─ 检查 finish_reason != "length"        ← 防 §3 的静默截断
  ├─ 检查确实产生了 tool_calls              ← auto 模式可能不调用
  ├─ jsonschema 校验 arguments              ← 无严格模式，必须自己验
  ├─ 校验 03 §3.2 的四条硬约束              ← close_condition 非空等
  └─ 失败 → 重试（上限 3 次，指数退避）
      └─ 三次都失败 → 该步骤标记 FAILED 写入日志，当天该步骤跳过
```

⚠️ **三次失败不得静默兜底。** 失败本身是实验数据：
如果某一步骤的失败率显著偏高，说明那一步的 prompt 或 schema 有问题，
不能用一个默认值糊过去，那会污染 30 天的结果。

## 6. Prompt Caching：30 倍价差是硬设计约束

实测 `usage` 返回 `prompt_cache_hit_tokens` / `prompt_cache_miss_tokens`，
缓存自动生效，无需显式声明断点。

价格（美元/百万 token，峰值时段）：

| | 输入命中 | 输入未命中 | 输出 |
|---|---|---|---|
| deepseek-v4-pro | $0.044 | $1.32 | $3.96 |
| deepseek-v4-flash | $0.014 | $0.44 | $1.32 |

**输入命中比未命中便宜 30 倍。** 这把「账本摘要前缀必须逐字节稳定」
从优化建议提升成**一等设计约束**：

- 前缀里不许出现时间戳、随机 ID、非确定性排序
- 账本摘要的序列化必须固定字段顺序（SQL 查询显式 `ORDER BY`）
- 易变内容（当天信号、当前预算）一律放到前缀之后

**离峰价格是峰值的一半。** 峰值时段为周一至周五 UTC 01:00–04:00 与 06:00–10:00
（北京时间 09:00–12:00、14:00–18:00）。日循环的唤醒时间**固定安排在离峰**
（建议北京时间凌晨 02:00），成本直接减半，且不影响实验——
唤醒时刻对三组一视同仁。

## 7. 成本估算

按峰值价保守估（离峰减半），每组每天：

| 层 | 输入 | 输出（含推理） | 成本 |
|---|---|---|---|
| 审议层（4 次调用） | ~65K（多数命中） | ~31K | ≈ $0.15 |
| 执行层（4 个行动的 agent 循环） | ~2M（多数命中） | ~150K | ≈ $1.20 |

- 单组 30 天 ≈ **$40**
- **三组（A/B/C）30 天 ≈ $120**，安排在离峰 ≈ **$60**

比原 Claude Opus 5 方案（$400~1100）低约一个数量级。

**后果不只是省钱**：预算不再是约束，意味着
（a）延长到 90 天可行（03 文档 §9 薄弱点 4 的缓解手段现在负担得起）；
（b）可以多跑几个随机种子，把单次运行的偶然性排除掉。

⚠️ 但注意：**成本池是 survival drive 的输入**（03 §2.1）。
真实成本降一个数量级，意味着 `cost_pool_total` 必须**按比例调小**，
否则 agent 永远撞不到降级线，survival drive 全程为 0，等于没有。
池子要按「合理行为撑完 30 天且有余量、浪费行为撞降级」来标定，
**不是按真实账单设**。

## 8. ⚠️ 模型漂移风险比 Claude 方案更高

`deepseek-v4-pro` 不是带日期的快照 ID，DeepSeek 可能原地更新模型。
30 天实验期内模型变化 = 实验分段失效。

两个廉价探测（成本可忽略，必须做）：

1. 每次调用记录 `response.model` 与完整 `usage` 写入日志
2. **每天跑一次固定 canary prompt**（固定 seed 无从设定，就固定 prompt +
   `reasoning_effort:"minimal"`），存下 `content` 与 `reasoning_tokens`。
   若 canary 输出突变，在结果里标记实验分段。

## 11. 与原设计的差异汇总

| 原设计 | 改为 | 原因 |
|---|---|---|
| Claude Agent SDK 作 L0 | DeepSeek Harness / OpenAI 兼容循环 | 换模型供应商 |
| `output_config.format` 严格结构化输出 | 函数调用 + 代码校验 + 重试 | §2，无严格模式 |
| 强制 `tool_choice` | `tool_choice:"auto"` + 强提示 | §2，thinking 模式不支持 |
| effort 作为省钱手段 | effort 作为算力分配设计 | §4 |
| Prompt caching 作为优化 | 前缀字节稳定作为一等约束 | §6，30 倍价差 |
| 30 天，成本是约束 | 30 天可扩到 90 天、多种子 | §7，成本降一个数量级 |
