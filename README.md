# driving-agent 文档索引

本项目研究一个问题：

> 一个没有人给它派活、但环境每天都在变的 Agent，连续运行 30 天，凭什么每天只挑其中几件事做？

不是再造一个 Agent Harness。Harness（Model / Tools / Skills / Memory / Loop / Sandbox）
是既有基础设施，直接复用。本项目只做它上面的一层：**动机与选择**。

## 三个已定边界（已确认）

| 边界 | 选择 | 换掉的话 |
|---|---|---|
| 稀缺性 | 每日不结转的行动预算（主）+ 成本总盘（背景压力） | 改 03 文档 §2.1 与配置 `budget.*` |
| 环境 | 有心跳的世界：仓库 + 订阅源 + 收件箱，无指令 | 改 03 文档 §3.1 的 World Adapter 集合 |
| 30 天产出 | 被事实检验过的世界模型/自我模型（预测—对账） | 改 02 文档 §3 与 04 文档的主指标 |

这三条是整个设计的地基。任何一条改动都会往下传导，改之前先读 01 文档第 3 节。

## 技术栈

模型 `deepseek-v4-pro`（OpenAI 兼容协议直连），凭证在 `.env`（已 gitignore）。
模型侧的每一条事实都经过实测验证，不是从文档推断——见
[05-模型与运行环境](docs/05-模型与运行环境.md)。

三处与原设计冲突、已导致设计改动的实测结论：

- 严格 JSON Schema **不可用** → 审议层改走函数调用 + 代码校验 + 有界重试
- 强制 `tool_choice` 在 thinking 模式下**不可用** → 只能 `auto` + 强提示
- 输入缓存命中比未命中便宜 **30 倍** → 「账本前缀逐字节稳定」升级为一等设计约束
